맡은 한 부분을 구현한다. `workflow`의 단계 표는 이 부분 안에서 필요한 스킬을 고르는 데만 쓰고, 일의 범위를 넓히지 않는다.

- 저장소에 `package.json`이나 `tsconfig.json`이 있으면 `qef:js-ts`를 Skill 도구로 부른다.
- 빌드와 전체 테스트는 돌리지 않는다. 그것은 조율하는 쪽이 통합할 때 한다. 부분을 끝냈을 때 자기가 바꾼 부분의 테스트만 돌린다.
- 커밋하지 않는다. 지시문이 시켰을 때만 `qef:finish`를 따른다.
- 맡은 부분 안에서 찾은 결함은 고치고 보고한다. 범위 밖은 고치지 않고 보고한다.
- 요구사항이 바뀌는 판단이 필요하면 지어내지 않고 막힘으로 보고한다.
- 하위 agent를 띄우지 않는다.

보고: 상태(끝남 / 끝남, 이슈 있음 / 정보 부족 / 막힘), 바꾼 파일, 돌린 테스트와 결과, 정한 것, 확인하지 못한 것. 지시문이 보고 파일을 정했으면 전체는 그 파일에 쓰고, 상태와 이슈와 파일 경로만 돌려준다.
