# 서브에이전트 지시 틀

메인 세션은 서브에이전트 지시를 이 틀로 쓴다. 기준 파일의 내용은 붙여 넣지 않고 **절대 경로와 절 이름으로 가리킨다.** 서브에이전트가 직접 읽는다. 그래야 단계마다 같은 기준이 같은 글자로 전달된다.

- **공통 지시는 파일로 한 번만 쓴다.** 한 단계에서 같은 틀로 여러 서브에이전트를 띄울 때(검토 관점들, 탐지자들, 반박자들), 아래 틀에서 서브에이전트마다 같은 부분을 `<실행 폴더>/briefs/<단계 id>-<맡은 일 묶음>.md`에 한 번 쓴다. 각 서브에이전트에게는 "그 파일을 읽고 따르라, 네가 맡은 것은 X, 읽을 것은 Y, 보고는 Z에"만 보낸다. 같은 틀을 메시지마다 다시 쓰지 않는다.
- 서브에이전트 종류는 `general-purpose`를 쓴다. 보고 파일을 써야 하기 때문이다. 예외: 요구사항 단계의 코드 읽기는 Explore로 해도 된다. 그때는 받은 요약을 메인 세션이 `run.md`의 "요구사항 단계 읽기"에 적어 둔다.
- 서로 독립적인 서브에이전트(검토 관점들, 탐지자들, 반박자들)는 **Agent 호출 여러 개를 한 메시지에 함께 보낸다.** 앞 결과가 필요한 것만 차례로 띄운다.
- 프로젝트 파일을 쓰는 서브에이전트는 한 번에 하나만 띄운다. 같은 작업 트리를 쓰기 때문이다.

## 틀

````
너는 qef 개발 절차에서 "<단계 이름>" 단계의 "<맡은 일>"을 맡은 서브에이전트다.
- mcp__qef__ 로 시작하는 도구를 부르지 마라. 다른 서브에이전트를 띄우지 마라. 사용자에게 묻지 마라.
- 프로젝트 파일은 Edit/Write로만 고친다. 셸로 파일 내용을 바꾸지 마라 (sed -i, >, tee 등). 쓰기가 막히면(샌드박스나 권한 규칙) 지금 단계의 규칙이다. 우회하지 말고 보고에 적어라. 파일을 지울 때는 설계 트리에 change=removed로 있는 파일만 `rm <경로>`로 하나씩 지운다.
- 설계 트리에 없는 파일을 만들지 마라. 단계를 제출할 때 트리 밖에서 바뀐 파일이 있으면 제출이 거부된다.
- <이 단계에서 프로젝트 파일을 쓰지 않는다면: 프로젝트 파일은 읽기만 한다.>
<스킬을 쓰는 단계면:> 먼저 Skill 도구로 `<스킬 이름>` 스킬을 불러와 이 단계에 해당하는 절차만 따르라. <쓰는 범위>. 스킬이 목록에 없으면 건너뛰고 진행하라. 사용자에게 묻기, 커밋·브랜치 생성, 설계 문서 저장, 다른 스킬로 넘어가기 같은 절차는 하지 마라.

## 작업
- 사용자 요청: <qef_start에 넘긴 한 줄>
- 작업 모드: <build|extend|refactor>
- 작업 언어: <qef_start에 넘긴 language>
- 프로젝트 루트: <절대 경로>

## 먼저 읽을 것
- 확정 요구사항: <실행 폴더>/requirements.json
  요구사항 문구와 userStatements(사용자 원문)가 어긋나 보이면 원문을 따르고, 어긋난 점을 보고에 적어라. 요구사항에 없는 상황은 rationale에 적힌 이유에 맞는 쪽으로 판단하라.
- 설계: <실행 폴더>/design/ 의 <단계 파일이 정한 파일>   (설계가 정해진 뒤 단계에서만)
- 기준: <스킬 폴더>/criteria/<파일>.md 의 "<절 이름>"
- <단계 파일이 더 넘기라고 한 것>

## 할 일
<단계 파일의 지시>

## 보고
- 결과 전체를 <실행 폴더>/reports/<보고 파일 이름>.json 에 아래 형식으로 써라.
  <단계 파일이 정한 형식>
- 보고 파일 맨 위에 `deviations`(이 지시와 다르게 한 것, 막힌 것, 우회한 것. 예: 명령에 시간 제한을 붙임, Write 대신 셸로 씀. 없으면 `[]`)를 넣어라.
- 모든 문장은 <작업 언어>로 쓴다. 코드 식별자, 경로, 명령, 사용자 원문 인용은 그대로 둔다.
- 답장에는 보고 파일 경로와 10줄 이내 요약만 쓴다.
````

## 보고 파일 이름

`<단계 id>-<맡은 일>[-<차수>].json`. 예: `design-research-codebase.json`, `common-review-lens-simplicity.json`, `rest-impl-parser-2.json`. 같은 이름이 이미 있으면 차수를 붙인다. 이전 보고를 덮어쓰지 않는다.

## 받은 보고 다루기

- 답장의 요약만 믿지 않는다. 다음 결정에 쓰는 값(지적, 판정, 실패 목록)은 보고 파일에서 읽는다.
- 보고 파일이 없거나 형식이 다르면 같은 지시로 한 번 다시 띄운다. 두 번째도 실패하면 그 사실을 사용자에게 알리고, 그 결과 없이 진행할지 묻는다.
- 보고에 다른 언어 문장이 섞여 있으면 사용자에게 보여주기 전에 작업 언어로 옮긴다.
