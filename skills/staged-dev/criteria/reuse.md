# 재사용·재발명 기준

이미 있는 것을 새로 만들지 않게 한다. 설계 직후(외부 라이브러리 검색)와 공통부·전체 검토(재발명 탐지)에서 쓴다.

## 외부 라이브러리로 바꿀 가치 판단 기준

- 바꿀 만한 것: 규격이나 엣지케이스가 복잡해 직접 짜면 틀리기 쉬운 문제 (예: CSV 파싱, 날짜·시간대, 암호화, URL·이메일 검증).
- 바꾸지 않을 것: 몇 줄짜리 단순 로직.
- 확인할 것: 최근 릴리스 시점, 사용량(다운로드·의존 프로젝트 수), 라이선스, 크기와 딸려오는 의존성, API가 이 작업에 맞는지.

## 설계 직후: 외부 라이브러리 검색

컴포넌트마다 서브에이전트 하나. 컴포넌트가 직접 구현하려는 기능 중, 아직 설치되지 않은 외부 라이브러리로 해결할 수 있는 것을 이 프로젝트 언어의 패키지 저장소(npm, PyPI, crates.io 등)와 웹에서 찾는다. 이미 설치된 의존성과 설계 조사 보고의 후보는 제외한다. 위 기준에 맞는 것만 보고한다. newCode에는 컴포넌트 이름과 대체될 기능을, source는 external-library로 적는다.

## 검토 단계: 재발명 탐지

탐지자 셋을 한 번에 띄운다.

- 직접 검색: 이번에 새로 작성된 함수·클래스·타입 각각에 대해 같은 일을 하는 것이 이미 있는지 직접 찾는다. 이 저장소의 기존 코드(이름·시그니처·핵심 로직으로 grep), 이미 설치된 의존성(매니페스트·lockfile과 그 API), 언어 표준 라이브러리. 파일:줄이나 API 이름 같은 확실한 근거가 있는 것만 보고한다.
- 조사 대조: 설계에서 reuse/extend로 정한 후보가 실제 코드에서 쓰였는지 확인한다. 조사된 후보 중 새 코드와 기능이 겹치는데 쓰이지 않은 것도 찾는다.
- 외부 라이브러리 검색: 이번에 새로 작성된 함수·모듈 각각에 대해, 아직 설치되지 않은 외부 라이브러리로 대체할 수 있는지 찾는다. 이미 설치된 의존성과 조사 후보는 제외한다. 위 기준에 맞는 것만 source를 external-library로 보고한다.

메인 세션은 세 보고의 후보를 합치고, newCode가 같은 것(앞뒤 공백·대소문자 무시)은 하나로 줄인다.

## 반박 검증

후보마다 반박자 둘을 한 번에 띄운다. **둘 다 반박에 실패해야 확정한다.** 하나라도 반박하면 확정하지 않는다. 후보끼리도 서로 독립이므로 모든 후보의 반박자를 한 메시지에 보낼 수 있다.

반박자 지시:

> 다음 '이미 있는 것을 새로 만들었다'는 지적을 반박해 보라. (newCode, existing, source, evidence)
> 두 코드를 직접 읽어라. 동작 차이, 성능, 라이선스, 버전, 이 프로젝트의 제약 때문에 기존 것을 못 쓰는 이유가 있으면 refuted=true. 불확실하면 refuted=true.

source가 external-library면 덧붙인다:

> 외부 라이브러리 후보다. 패키지 저장소에서 실제 정보를 확인하라. 위 "외부 라이브러리로 바꿀 가치 판단 기준"을 따르라. 몇 줄짜리 단순 로직을 대체하는 것이면 refuted=true.

## 확정된 것의 처리

- 설치된 것(codebase, dependency, stdlib)으로의 교체: 검토 지적으로 `issues.json`에 넣는다. severity는 major, problem은 "이미 있는 <existing> (<source>)와 같은 기능을 새로 만들었다: <evidence>", fix는 "<existing>를 쓰도록 바꾸고 중복 코드를 삭제한다. 그 코드의 테스트를 지우거나 옮겨야 하면 testDisputes로 올린다."
- 외부 라이브러리(external-library): 의존성 추가라서 자동 반영하지 않는다. 다음 체크포인트에서 사용자에게 후보마다 무엇을 대체하는지와 근거를 보여주고 채택 여부를 묻는다.
- 반박된 것도 `reuse.json`에 반박 이유와 함께 남긴다. 사람이 훑어볼 수 있게 하기 위해서다.

## 보고 형식

탐지·검색:

```json
{ "duplicates": [{ "newCode": "새로 만든 심볼 이름과 파일:줄 (설계 단계면 컴포넌트와 기능)", "existing": "이미 있는 대체물: 파일:줄, 패키지 API, 표준 라이브러리 API", "source": "codebase | dependency | stdlib | external-library", "evidence": "둘이 같은 일을 한다는 구체적 근거" }] }
```

반박:

```json
{ "refuted": true, "reason": "근거" }
```
