# 검증 기준

동작이 바뀌지 않았다는 것, 또는 바라는 대로 바뀌었다는 것을 무엇으로 보일지 정한다. 근거: Kent Beck, Test Desiderata.

## 기준선

- 시작할 때 빌드, 타입 검사, lint, 테스트를 지금 상태에서 한 번 돌리고 명령과 결과를 `run.md`에 적는다.
- 이미 실패하는 것은 그대로 적는다. 끝낼 때 같은 실패는 나빠진 것이 아니다. 새 실패만 나빠진 것이다.
- 테스트 프레임워크 자체가 깨져 있으면(예: 경로 설정이 없어 테스트가 뜨지 않음) 고치는 일을 첫 단위로 둔다. 테스트 프레임워크 설정은 겉보기 동작이 아니다.

## 돌리는 범위

- 고치는 동안에는 바꾼 패키지와 그것에 의존하는 패키지만 빌드하고 테스트한다(pnpm이면 `--filter "...<패키지>"`). 커밋하지 않는 subagent는 여기까지만 돌린다.
- 다른 명령을 이미 안에 포함한 명령은 함께 돌리지 않는다. 명령마다 무엇을 포함하는지는 `package.json`의 scripts에서 확인한다.
- 리포지토리 전체 명령은 커밋하는 쪽이 리뷰와 고침이 끝난 뒤, 커밋하기 직전에 한 번 돌린다. 결과는 로그 파일로 남기고, working tree가 바뀌지 않았으면 다시 돌리지 않고 그 로그를 읽는다.

## 동작이 같다는 근거 (refactor, extend에서 건드리는 곳)

동작이 같다는 근거는 이미 있는 테스트, 빌드, 타입 검사를 기준선과 비교한 것이다. 새 테스트로 지금 동작을 고정하지 않는다. 지금 동작에는 결함이 섞여 있을 수 있고, 고정하면 나중에 결함을 고칠 때 걸림돌이 된다. 이것들로 확인하지 못한 동작은 "확인하지 못한 것"으로 보고한다.

## 기존 테스트

- 기대값은 바꾸지 않는다. 기대값을 바꿔야 통과한다면 동작이 바뀐 것이다. 사용자가 그 변경을 허용하지 않았으면 그 단위를 보류하고 묻는다. 허용했으면 "끝낼 때"대로 의도한 변경으로 적고 테스트를 맞춘다.
- 옮긴 파일의 import 경로나 바뀐 내부 이름만 따라가는 수정은 해도 된다. 무엇을 바꿨는지 판단 기록에 적는다.
- 지금 모양에 묶인 테스트(내부 경로 import, mock 대상, 호출 횟수 검증)가 많으면, 옮길 때 옛 경로에 re-export를 잠시 두는 대신 테스트의 import를 바꾼다. 옛 것과 새 것을 함께 돌리는 임시 장치는 남기지 않는다.

## 새 테스트 (build, extend)

- 할 수 있게 되는 것마다 관찰 가능한 결과를 확인하는 테스트를 하나 이상 둔다. 정상, 오류, 경계(빈 값·0·최대·경계±1)를 넣는다.
- 이름은 "<조건>일 때 <결과>"로 쓴다. AAA(Arrange-Act-Assert) 패턴으로 쓰고, Act는 한 번만 한다.

## 좋은 테스트의 신호

- 구현에 묶이지 않는다: private 함수나 내부 상태에 직접 접근하지 않고, 내부 모듈의 호출 순서를 검증하지 않는다.
- 검증이 약하지 않다: assertion이 있고, 결과 전체를 확인하고, 기대값을 구현과 같은 로직으로 계산하지 않고 리터럴로 적는다. "이 테스트는 어떤 버그를 잡는가?"에 한 문장으로 답할 수 있어야 한다.
- 항상 같은 결과: 시각은 고정하거나 주입하고, 난수는 시드를 고정하고, 파일은 임시 디렉터리, 네트워크는 가짜로 대체한다. 테스트끼리 상태를 공유하지 않는다.
- mock은 외부 API, DB, 파일 시스템, 시계, 난수에만 쓴다. 같은 코드베이스의 내부 모듈은 실제 객체를 쓴다.

## 끝낼 때

- 기준선과 같은 명령을 다시 돌려 비교한다. 새 실패가 없어야 한다.
- 사용자가 겉보기 동작이 바뀌는 것을 허용한 작업이면, 새로 실패한 테스트마다 "의도한 변경"(어떤 구조 결정 때문인지)과 "망가진 것"으로 나눠 적는다. 망가진 것은 고친다. 의도한 변경이면 그 테스트를 바뀐 동작에 맞추고, 무엇을 바꿨는지 판단 기록에 적는다.
- 테스트로 확인하지 못한 겉보기 동작(예: 서버를 DB와 함께 띄우지 못함)은 "확인하지 못한 것"으로 보고한다. 확인했다고 쓰지 않는다.
- 통합 테스트나 엔드-투-엔드 테스트가 돌아가는 프로젝트면 그것도 돌린다. 가능하면 바꾸기 전 커밋에서도 같은 결과인지 본다.
