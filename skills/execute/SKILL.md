# execute

직접 할지, 맡길지, 나란히 돌릴지는 전역 `CLAUDE.md`의 "일을 나누는 방식"으로 고른다. 이 스킬은 개발 일에서 그 안을 어떻게 하는지를 정한다.

## 어느 agent

| 맡기는 일 | agent |
|---|---|
| 개념·경계의 설계 초안 | `qef:designer` |
| 정해진 부분의 구현, 코드 옮기기, 그 부분의 테스트 | `qef:implementer` |
| 지금 구조의 평가, 요구사항 파일 점검(`qef:intake`), 통합 때의 요구사항 대조(`qef:finish`) | `qef:reviewer` |

스킬은 agent 정의로 실려 들어가니 지시문에 다시 적지 않는다.

## 지시문

사용자 원문(또는 파일 경로), 맡기는 한 부분, 경계, 앞 부분의 인터페이스, 돌려줄 형식을 적는다. 세션 이력을 붙이지 않는다. 큰 산출물은 파일로 두고 경로를 넘긴다. 구현을 맡길 때는 보고 파일의 경로도 정해 준다. 돌아온 글은 조율하는 쪽의 context에 끝까지 남기 때문이다. 목표를 "테스트를 통과시켜라"로 쓰지 않는다.

## 보고

| subagent의 보고 | 조율하는 쪽이 하는 일 |
|---|---|
| 끝남 | 그 부분의 스냅샷 diff를 읽어 판단한다. 보고는 정보다 |
| 끝남, 걸리는 것 있음 | 걸리는 것을 읽고 요구사항에 대 본다 |
| 정보 부족 | 빠진 것을 주어 다시 맡긴다 |
| 막힘 | 무언가를 바꿔 다시 맡긴다. 지시, 범위, 모델 중 하나다. 그대로 재시도하지 않는다 |

바꿔 맡겨도 같은 곳에서 다시 막히면 더 돌리지 않는다. 구조를 의심하고(`qef:model`, `qef:layout`), 무엇을 바꿔 봤는지와 함께 사용자에게 보인다.

조율하는 쪽이 subagent의 일을 대신 고치지 않는다. 고칠 일은 그 일을 맡은 쪽에 돌려보낸다.

## 나란히 돌리기

- 서로의 결과가 필요 없고 같은 파일을 건드리지 않는 일만 나란히 돌린다.
- 관련된 실패는 하나를 고치면 다른 것도 풀릴 수 있으니 나누지 않고 함께 본다. 실패는 원인이 같은 것끼리 묶어 맡긴다.
- 돌아오면 충돌을 보고, 통합은 조율하는 쪽이 한다. 전체 테스트와 빌드는 그때 한 번 돌린다.

## 실행하는 동안

- 시작 전에 부분 사이의 인터페이스가 맞는지 한 번 훑는다.
- 부분을 끝낼 때마다 스냅샷(`qef:workflow`의 "기록과 보고")과 함께 `progress.md`에 적고, 끝났다고 적힌 부분은 다시 맡기지 않는다.
- 통합 뒤 고칠 항목이 여럿이면 항목마다 subagent를 띄우지 않고 하나에 묶어 맡긴다. subagent마다 context를 처음부터 다시 쌓기 때문이다.
- 계획이 틀렸으면 표준이나 상식으로 정해지는지 보고, 정해지면 정해서 `progress.md`에 적는다. 요구사항이 바뀌는 일이면 사용자에게 묻는다.
- 코드가 틀렸으면 그 자리의 원인을 고친다. 단계의 출력에 맞추려고 증상을 덮지 않는다.
- 작업마다 reviewer를 두지 않는다. subagent가 다른 subagent를 더 띄우지 않게 둔다.
- 맡길 때 모델을 밝힌다. 밝히지 않으면 세션 모델을 물려받는다. 일을 끝낼 수 있는 등급 가운데 왕복 수까지 넣어 싼 쪽을 고르고, 통합 때의 요구사항 대조는 쓸 수 있는 가장 강한 등급에 맡긴다.
- subagent를 기다릴 때 짧게 polling하지 않는다.
- 멈춰서 묻는 것은 전역 결정권 표의 사용자 칸뿐이다. 답을 기다리는 동안 그 답과 무관한 부분은 계속한다.
