# investigate

증상이 아니라 원인을 찾고, 같은 원인이 있는 다른 곳까지 찾는다. 이 원칙은 이 스킬을 호출할 때만이 아니라 언제나 적용된다. 여기에는 기법을 둔다.

절마다 의도, 규칙, 확인할 것을 둔다. 규칙에 없는 상황은 그 절의 의도로 판단한다. 사용자가 실제 프로젝트에서 짚은 장면은 [references/cases.md](references/cases.md)에 있다.

## 기법

**의도.** 원인은 대개 증상이 난 곳보다 앞에, 그리고 상관없어 보이는 차이 속에 있다. 상황에 맞는 기법을 고르지 않으면 증상 주변만 맴돈다.

| 상황 | 하는 일 |
|---|---|
| 오류가 났다 | 오류를 끝까지 읽고, 재현하고, 최근 변경을 본다 |
| 간헐적으로 일어난다 | 일어나는 조건(브라우저, 순서, 시각, 데이터)을 좁혀 재현 방법부터 찾는다 |
| 여러 구성 요소를 지난다 | 경계마다 들어오고 나가는 값을 한 번에 기록해 어디서 깨지는지 본다 |
| 깊은 곳에서 터진다 | 호출 체인을 거슬러 올라가 잘못된 값이 처음 생긴 곳을 찾는다 |
| 비슷한 코드는 동작한다 | 둘의 차이를 빠짐없이 나열한다. 상관없어 보이는 차이도 지우지 않는다 |
| 참조 구현이 있다 | 끝까지 읽는다 |
| 앞선 작업이 남긴 것이 있을 수 있다 | 남은 파일, 프로세스, 캐시, 빌드 아티팩트, 브랜치를 확인한다 |
| 테스트가 파일이나 상태를 오염시킨다 | 테스트를 하나씩 돌려 오염시키는 테스트를 찾는다 |
| 타이밍에 따라 실패한다 | 임의의 sleep을 늘리지 않고 기다릴 조건을 찾는다 |
| 실패가 여럿이다 | 원인이 같을 만한 것을 묶어 함께 본다. 하나를 고치면 다른 것도 풀릴 수 있다 |
| 출력이 길다 | 파일로 보내고 필요한 곳을 읽는다 |

**확인할 것**
- [ ] 보고된 증상을 재현했거나, 재현하지 못한 이유와 시도한 조건을 적었다.

## 가설

**의도.** 추측으로 코드를 바꾸면 증상이 사라져도 원인은 모른 채 남는다. 확인하지 않은 원인을 원인이라고 말하면, 그 위에 쌓은 수정이 모두 헛돈다.

- 가설은 하나씩 세우고, 그 가설만 구분하는 가장 작은 관찰을 한다. 추측으로 코드를 바꿔 보지 않는다.
- 찾은 원인이 맞는지부터 의심한다. 원인이라고 말하기 전에, 그 원인만 바꾸면 증상이 생기고 사라지는지 본다.
- 모르면 모른다고 말하고, 무엇을 봤고 무엇이 남았는지 적는다.

**확인할 것**
- [ ] 원인이라고 말한 것마다, 그것만 바꿨을 때 증상이 달라지는 것을 봤다.

## 원인이 코드 밖이면

**의도.** 조사가 덜 끝난 것을 환경 탓으로 돌리면 같은 문제가 다시 나온다. 반대로 드문 외부 실패마다 메커니즘을 덧붙이면 그 메커니즘이 구조를 어지럽힌다.

- 원인이 환경, 타이밍, 외부 시스템으로 드러나면 조사한 것과 그렇게 판단한 근거를 남기고, 그에 맞게 처리한다(재시도, timeout, 오류 메시지). 조사가 덜 끝난 것을 환경 탓으로 돌리지 않는다.
- 드물게 일어나는 외부 실패를 막으려고 메커니즘을 계속 더하지 않는다. 사람이 처리하는 편이 싸면 실패를 알아볼 수 있게 보이고, 처리 방법을 남긴다.

**확인할 것**
- [ ] 코드 밖이라고 판단한 근거(재현 조건, 로그, 외부 응답)가 남아 있다.

## 고치는 위치

**의도.** 증상이 난 곳에서 고치면 같은 원인이 다른 곳에서 다시 나오고, 고칠 때마다 검사가 덧붙어 구조가 무거워진다.

- 증상이 난 위치가 아니라 원인이 생긴 위치에서 고친다. 그 결함이 어느 계층의 결정에서 나왔는지 묻는다.
- 원인을 고치는 대신 값이 지나는 계층마다 검사를 덧붙이지 않는다.
- 재현한 오류는 고친 뒤 같은 재현을 한 번 다시 본다. 그 오류가 사라졌다는 근거이고, 일이 끝났다는 근거는 아니다. 끝났는지는 요구사항에 대 본다(OpenSpec 변경이면 proposal의 Done When). 재현을 테스트로 남길지는 `qef:testing`의 기준으로 정한다.
- 수정이 거듭 실패하면 그 위치를 더 고치지 않고 구조를 의심한다(`qef:model`, `qef:layout`).

**확인할 것**
- [ ] 고친 곳이 원인이 생긴 계층이고, 같은 원인이 있는 다른 곳도 찾았다.
- [ ] 고친 뒤 같은 재현을 다시 봤다.
