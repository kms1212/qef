# investigate

원인을 찾고 같은 원인의 다른 곳까지 찾는 원칙은 전역 `CLAUDE.md`의 "판단의 기준"을 따른다. 그 원칙은 이 스킬을 부를 때만이 아니라 언제나 적용된다. 여기에는 기법만 있다.

## 기법

| 상황 | 하는 일 |
|---|---|
| 오류가 났다 | 오류를 끝까지 읽고, 재현하고, 최근 변경을 본다 |
| 여러 구성 요소를 지난다 | 경계마다 들어오고 나가는 값을 한 번에 기록해 어디서 깨지는지 본다 |
| 깊은 곳에서 터진다 | 호출 사슬을 거슬러 올라가 잘못된 값이 처음 생긴 곳을 찾는다 |
| 비슷한 코드는 동작한다 | 둘의 차이를 빠짐없이 나열한다. 상관없어 보이는 차이도 지우지 않는다 |
| 참조 구현이 있다 | 끝까지 읽는다 |
| 테스트가 파일이나 상태를 더럽힌다 | 테스트를 하나씩 돌려 더럽히는 테스트를 찾는다 |
| 타이밍에 따라 실패한다 | 임의의 sleep을 늘리지 않고 기다릴 조건을 찾는다 |
| 실패가 여럿이다 | 원인이 같을 만한 것을 묶어 함께 본다. 하나를 고치면 다른 것도 풀릴 수 있다 |
| 출력이 길다 | 파일로 보내고 필요한 곳을 읽는다 |

## 가설

가설은 하나씩 세우고, 그 가설만 가르는 가장 작은 관찰을 한다. 추측으로 코드를 바꿔 보지 않는다. 모르면 모른다고 말하고, 무엇을 봤고 무엇이 남았는지 적는다.

## 원인이 코드 밖이면

원인이 환경, 타이밍, 바깥 시스템으로 드러나면 조사한 것과 그렇게 판단한 근거를 남기고, 그에 맞게 처리한다(재시도, timeout, 오류 메시지). 조사가 덜 끝난 것을 환경 탓으로 돌리지 않는다.

## 고치는 자리

- 증상이 난 자리가 아니라 원인이 생긴 자리에서 고친다. 그 결함이 어느 층의 결정에서 나왔는지 묻는다.
- 원인을 고치는 대신 값이 지나는 층마다 검사를 덧대지 않는다.
- 재현한 오류는 고친 뒤 같은 재현을 한 번 다시 본다. 그 오류가 사라졌다는 근거이고, 일이 끝났다는 근거는 아니다(`qef:finish`). 재현을 테스트로 남길지는 `qef:testing`의 기준으로 정한다.
- 고침이 거듭 실패하면 그 자리를 더 고치지 않고 구조를 의심한다(`qef:model`, `qef:layout`).
