# ui

UX 기준과 화면 공통의 판단 기준(근거 차례, 근거 없는 추가를 막는 순서, 이전 버전 대조)은 `qef:ux`에 있고 여기서도 그대로 따른다. 이 스킬은 모양만 다룬다.

## 같은 것은 같게

- 같은 종류의 요소는 모양과 자리가 같다. 같은 종류인데 높이, 여백, 모서리, 아이콘 스타일이 조금씩 다르면 결함이다. 같은 종류의 입력(예: 비밀값)은 같은 곳에서 등록한다.
- 현재 위치는 한 항목만 강조한다.
- 업무 화면은 꾸미지 않고 익숙한 표준 컴포넌트를 쓴다. 표준 동작을 새로 지어내지 않는다.
- 색, 간격, 글꼴 같은 값은 이름 붙은 값(디자인 토큰)으로만 쓴다.
- 기존 정체성(로고와 그 자리)은 바꾸라는 요구사항이 없으면 그대로 둔다.

## 정렬과 overflow

- 정렬은 margin을 맞춰 만들지 않고 구조(flex, grid, gap)로 만든다. 아이콘과 글자는 한 줄의 기준선에 맞춘다.
- 표의 열은 머리와 셀이 맞는다. 숫자는 오른쪽 정렬하고 `tabular-nums`를 쓴다.
- 다이얼로그와 텍스트 필드는 긴 문자열, 좁은 폭, 200% 확대에서 넘치지 않는다. 오버레이는 overflow로 잘리는 조상 안에 두지 않고 `<dialog>`나 popover로 띄운다.

## 상태

- 상호작용하는 요소마다 기본, hover, focus, active, disabled, loading, error 상태를 설계한다. 목록과 표는 빈 상태와 오류 상태도 설계한다.

## 확인

- 렌더링 결함(overflow, 겹침, 열 어긋남)은 에이전트가 화면을 봐서 잘 찾지 못한다. 이전 버전이 있으면 바꾸기 전에 뜬 screenshot과 견준다. 이전 버전이 없는 새 화면은 「사람이 볼 것」에 올린다.
- 접근성 감사는 `design:accessibility-review`로 한다.
