# commit

커밋은 사용자가 시킬 때만 한다. 시켰으면 이 절차를 거친 뒤 한다. 일이 끝났는지는 여기서 보지 않는다(`qef:finish`).

## 절차

1. `git status`와 `git diff`로 들어갈 것을 보고, 파일마다 아래 표에서 행을 찾는다. 어느 행에도 맞지 않으면 커밋하지 않고 묻는다. 시킨 범위의 파일만인지도 본다.

   | 파일 | 저장소에 |
   |---|---|
   | 코드, 테스트, 빌드·실행 설정, 그 프로젝트를 쓰거나 개발하는 사람이 읽는 문서 | 추적한다 |
   | 빌드 산출물, 의존성 캐시, 실행 중에 생기는 파일(log, 임시 파일), OS·편집기가 만드는 파일 | 추적하지 않고 프로젝트 `.gitignore`에 넣는다 |
   | 시크릿, 한 사람의 컴퓨터에만 맞는 설정 | 추적하지 않는다 |
   | 에이전트 지시 파일(`CLAUDE.md`, `AGENTS.md` 등) | 사용자의 규칙을 따른다 |
   | 조사 기록과 보고서, 계획, 작업 경위, 에이전트가 쓴 메모 | 추적하지 않는다. 일 파일은 `.qef/`에, 그 밖의 것은 저장소 밖에 둔다 |

2. 프로젝트의 포매터와 lint를 커밋할 파일에 돌린다.
3. 바꾼 부분의 테스트만 돌린다. 이미 그 부분을 끝낼 때 돌렸고 그 뒤로 바꾸지 않았으면 다시 돌리지 않는다.
4. 파일을 이름으로 스테이징하고, 왜 바꿨는지를 적어 커밋한다.

사용자가 단위마다 커밋하라고 했으면 그 단위를 따른다.

## 커밋 게이트

qef의 hook은 `git commit` 앞에서 저장소 루트의 `.qef/commit-check`를 실행하고, 실패하면 커밋을 막는다. 판단이 필요한 것은 넣지 않고, lint와 바꾼 부분의 테스트처럼 결정론적인 것만 넣는다.

- 실행 파일로 두고, 커밋될 파일 목록을 표준 입력으로 줄마다 받는다. 0이 아닌 코드로 끝나면 막힌다.
- 프로젝트가 이미 git pre-commit hook을 쓰면 만들지 않는다.
- 이 파일이 없으면, 프로젝트의 lint와 테스트 명령으로 만들지 사용자에게 한 번 묻는다.
- 막히면 원인을 고친다. `--no-verify`로 넘기지 않는다.
